# city2graph 0.3.1 → 0.4.0 Migration Report — Liverpool Case Study Re-run

Date: 2026-06-12. Environment pinned to `city2graph[cpu]==0.4.0` (uv.lock updated).
Model architectures, hyperparameters, and random seeds are unchanged
(`configs/experiment_config.yaml` untouched; determinism smoke test passed).
All differences below are attributable to the 0.4.0 edge-index change:
graphs are now undirected and `edge_index` stores **both directions**,
making message passing symmetric (0.3.1 stored one direction only).

Raw data integrity: SHA-256 checksums of all 13 files under `data/raw/` are
**identical** before and after the re-run.

The previous (0.3.1) outputs are preserved in `data/outputs_v0.3.1/`.

## 1. Graph structure (old vs new)

| Relation | 0.3.1 rows (one direction) | 0.4.0 undirected pairs | 0.4.0 edge_index entries |
|---|---|---|---|
| `('oa','contig','oa')` | 4,782 | 4,782 (unchanged) | 9,564 |
| `('street_connector','is_connected_to','street_connector')` | 65,386 | 65,386 (unchanged) | 130,772 |
| `('bus_station','is_next_to','bus_station')` | 2,290 | 2,290 (unchanged) | 4,580 |
| `('oa','15_min_walk','oa')` | 28,518 | **28,265** (−253, −0.9%) | 56,530 |
| `('oa','15_min_multi','oa')` | 69,999 | **69,403** (−596, −0.9%) | 138,806 |

- Base relations are structurally identical; counts double only in `edge_index`.
- The 15-minute metapath relations shrink slightly (−0.9%) because
  `add_metapaths_by_weight()` in 0.4.0 computes shortest paths under fully
  undirected semantics and emits canonical (deduplicated) pairs.
- 0.4.0's `reverse_edge_types="auto"` adds reversed cross-type relations
  (`('street_connector','rev_is_nearby','oa')` etc.) to the HeteroData.
  These are **not** used by the models (HAN-GAE consumes only
  `('oa', metapath, 'oa')` relations) and do not affect training.

### Edge-count definition (Table B.2)
Counts are reported **per undirected pair** (one row per pair, as returned by
`pyg_to_gdf()`), not per direction. The underlying `edge_index` stores both
directions (2× the pair count). This is documented in a comment in
`05_visualization.ipynb` where `edge_relation_descriptive_stats.csv` is built,
and keeps the new values directly comparable with the published ones.

## 7. Code changes made for 0.4.0

- `pyproject.toml`: `city2graph[cpu]==0.4.0`, added `tol-colors==2.0.0`.
- `01_data_processing.ipynb`: `segments_to_graph(processed_streets, directed=False)`
  (canonical unordered node-id pairs; parallel street segments keep an
  `edge_key` index level that round-trips through GPKG).
- `02_graph_construction.ipynb`: street edges re-indexed as
  `["from_node_id","to_node_id","edge_key"]`; bus (`travel_summary`) edges get
  an `edge_key` level via `groupby.cumcount()` (7 stop pairs have parallel
  edges, which 0.4.0 validates instead of silently duplicating).
- `notebooks_samples/morphology.ipynb`: private/public → place/movement
  (node keys, edge-type tuples, variables, panel titles).
- `scripts/benchmark_gdf_to_pyg.py`: new benchmark script.
- Notebook execution note: run with `JUPYTER_PREFER_ENV_PATH=1` — the
  user-level kernelspec `~/Library/Jupyter/kernels/python3` points to a
  deleted venv (`Liverpool/H2-GAE/.venv`) and otherwise shadows this
  project's kernel.
